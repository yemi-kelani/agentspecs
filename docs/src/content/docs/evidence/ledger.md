## Conflicts

Rows that point different ways. Each conflict names its rows and says what the disagreement does and does not cover.

### C1: Do context files raise or lower cost?

Rows: [R1a](#r1a), [R2](#r2).

R1a found that context files raised inference cost by about 20% and added agent steps; R2 found that an AGENTS.md lowered median runtime by 28.6% and median output tokens by 16.6%. The studies measure different things (mean dollar cost and steps across four agents against median runtime and token counts for one agent), and R2 found no change in total tokens, so its result does not contradict R1a on cost. The real tension is output tokens: reasoning tokens rose by up to 22% in R1 and output tokens fell in R2. R2 did not measure correctness. Neither study tested task specs.

### C2: Do file size and position matter?

Rows: [R3](#r3), [R3a](#r3a), [R4](#r4), [R6](#r6), [R5d](#r5d).

R3 found no effect of instruction-file length (25 to 500 lines) and R3a no effect of where one rule sat in the file, while R6 found a U-shape in which information in the middle of the input was used worst, and R4 found accuracy falling as the number of instructions grew. R3 against R4 is not a direct conflict: R3 varied filler around one scored rule, R4 varied how many rules were scored at once. R3a against R6 is a partial tension, since R6 saw U-shapes at input sizes close to R3a’s 2-3k-token file. Possible reasons include a retrieval question against an always-on rule, position within a file against position within the whole prompt, 2023 against 2026 models, and R3a’s detection limit of about 6 points. R5d also found no position effect in its retrieval task.

### C3: Does always-loaded context help?

Rows: [R1](#r1), [R20](#r20).

R1 found that always-loaded context files gave no general gain in task success, while R20 found that an always-loaded docs index in AGENTS.md reached a 100% pass rate where an on-demand skill reached 53%. R20 tested framework APIs absent from the model’s training data and does not disclose its sample size; R1 tested ordinary Python repositories. The two are compatible if context helps only when it carries facts the model cannot get elsewhere.

Caveat: One open-source scanner (NVIDIA SkillSpector) and three open-weight model stacks; success (evasion plus payload delivery plus task completion) judged by an LLM, not humans; transfer to commercial scanners untested; preprint revised 2026-10-08. `b-pretext-evasion`

## How tools and formats work

- <span id="r7c"></span>**R7c** · Böckeler reports that Tessl, then in private beta, was the only one of the three tools explicitly aiming at spec-anchored development and exploring spec-as-source, mapping one spec to one code file and marking generated code as not to be edited, though repeated generation from the same spec was non-deterministic. Source: [Understanding Spec-Driven-Development: Kiro, spec-kit, and Tessl](https://martinfowler.com/articles/exploring-gen-ai/sdd-3-tools.html) (martinfowler.com). Verified 2026-10-22. - <span id="r130"></span>**R130** · AGENTS.md came out of a collaboration across coding-agent vendors and is now stewarded by the Agentic AI Foundation under the Linux Foundation. Source: [AGENTS.md](https://agents.md/) (agents.md). Verified 2026-10-09. Caveat: Governance facts as stated on the format's own site. `a-agentsmd-stewardship`
- <span id="r131"></span>**R131** · In Claude Code, context: fork runs a skill as the prompt of a new subagent that does not see the conversation history, so the skill must be self-contained and contain an explicit task. Source: [Extend Claude with skills](https://code.claude.com/docs/en/skills) (code.claude.com). Verified 2026-10-09. Caveat: This corrects the prior report's 'forked subagent' wording: despite the name, the subagent does not inherit the conversation. `a-cc-skill-context-fork`
- <span id="r132"></span>**R132** · Claude Code truncates each skill's combined description and when_to_use text at 1,536 characters in its skill listing (a configurable cap), and advises putting the key use case first. Source: [Extend Claude with skills](https://code.claude.com/docs/en/skills) (code.claude.com). Verified 2026-10-09. Caveat: This is a Claude Code implementation detail that may change by version. Other clients truncate differently or not at all. `a-cc-skill-desc-1536`
- <span id="r133"></span>**R133** · Claude Code adds its own frontmatter fields to the Agent Skills format, including when_to_use, disable-model-invocation, context: fork, agent and paths (glob-scoped activation), and treats every field as optional, while the open spec requires name and description. Sources: [Extend Claude with skills](https://code.claude.com/docs/en/skills) (code.claude.com); [Specification](https://agentskills.io/specification) (agentskills.io). Verified 2026-10-09. - <span id="r134"></span>**R134** · Claude Code's skill listing has a character budget of 1% of the model's context window. When it overflows, the least-used skills lose their descriptions first, which removes the keywords Claude uses to match them to requests. Source: [Extend Claude with skills](https://code.claude.com/docs/en/skills) (code.claude.com). Verified 2026-10-09. Caveat: Claude Code only, configurable, and version-dependent. `a-cc-skill-listing-budget`
- <span id="r135"></span>**R135** · In Claude Code an invoked skill's content stays in the conversation on later turns, so each line is a recurring token cost. After compaction, the first 5,000 tokens of each recent skill are re-attached within a combined 25,000-token budget. Source: [Extend Claude with skills](https://code.claude.com/docs/en/skills) (code.claude.com). Verified 2026-10-09. Quote: “every line is a recurring token cost”. Caveat: This is Claude Code behavior. Older skills can be dropped after compaction when many have been invoked. `a-cc-skill-persist`
- <span id="r136"></span>**R136** · Cursor project rules are .mdc files in .cursor/rules with four application modes: Always Apply, Apply Intelligently (decided from the description), Apply to Specific Files (glob match) and Apply Manually (@-mention). Source: [Rules](https://cursor.com/docs/rules) (cursor.com). Verified 2026-10-09. Caveat: This is Cursor-specific; plain .md files in .cursor/rules are ignored by the rules system. `a-cursor-rule-types`
- <span id="r137"></span>**R137** · Anthropic advises matching how specific instructions are to how fragile the task is: loose text guidance where many approaches work, and exact scripts with few or no parameters where operations are error-prone or must follow a fixed sequence.
