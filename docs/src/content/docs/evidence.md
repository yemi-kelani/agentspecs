Every claim on this site starts with one of four labels. This page defines them, sums up what the research supports and where it stops, then lists every verified claim, source, quote and dropped claim in the site's evidence file.

## Labels

- [Established] Vendor documentation, or several independent sources that agree. It tells you how a tool or format works, not whether it improves results.
- [Evidence] A specific study or measured report. Read it with its caveat, which always sits in the same paragraph or list item.
- [Heuristic] A practitioner's rule of thumb. It may be useful, but nobody measured it, so it is never a finding.
- [Proposal] A design choice this specification makes. It is what Agent Specs asks you to do, not something a study tested.

A label covers the sentence, list item or table cell it starts. Every badge on the site links back to this section.

## What the research shows

- [Evidence] Long inputs make models less reliable. Across 18 models, performance grew less reliable as input length increased, even on simple retrieval ([Chroma, 2025](https://www.trychroma.com/research/context-rot)), and models used information in the middle of a long input worst ([Liu et al., 2023](https://arxiv.org/abs/2307.03172)). Caveat: synthetic retrieval tasks on 2023–2025 models, not coding agents.
- [Evidence] Instructions given in pieces get lost. Revealing one instruction over several turns cut performance by 39% on average, and putting the pieces back into a single prompt recovered about 95% of it ([Laban et al., 2025](https://arxiv.org/abs/2505.06120)). Caveat: simulated users in chat tasks, not agentic coding runs.
- [Evidence] A written rule changes behaviour but does not guarantee it. Under the best conditions tested, agents applied a required annotation to about two-thirds of functions, against none without the rule ([McMillan, 2026](https://arxiv.org/abs/2605.10039)). Caveat: one trivial rule, mostly one model and two codebases.
- [Evidence] Context files cost more without clearly paying back. Adding an AGENTS.md-style file did not significantly change task success but raised inference cost by about 20% ([Gloaguen et al., 2026](https://arxiv.org/abs/2602.11988)). Caveat: Python repositories and four agent setups; task plans and skills were not tested.
- [Evidence] A skill left to the agent's discretion often goes unused. In Vercel's evals the agent never invoked an available skill in 56% of cases ([Vercel, 2026](https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals)). Caveat: one vendor's eval on one framework, with undisclosed models and harness.
- [Established] Vendors converge on short instruction files that point to detail elsewhere: under 500 lines for SKILL.md and Cursor rules, under 200 per CLAUDE.md, about 100 for one OpenAI team's AGENTS.md ([Agent Skills](https://agentskills.io/specification), [Cursor](https://cursor.com/docs/rules), [Claude Code](https://code.claude.com/docs/en/memory), [OpenAI](https://openai.com/index/harness-engineering/)). None of these figures comes from a published experiment.

## What it does not show

The research above is real but narrow. Read the rest of the site with these limits in mind.

- [Evidence] File length had no detectable effect between 25 and 500 lines. In 1,650 Claude Code sessions, CLAUDE.md files of 25, 100, 250 or 500 lines did not change how often the agent followed a required rule, and splitting the file or nesting it gave no detectable gain ([McMillan, 2026](https://arxiv.org/abs/2605.10039)). Caveat: the rule was a trivial comment marker, files over 500 lines were not tested, and a long file still costs tokens in every session.
- [Proposal] The structure's benefits are mainly token economy, isolation and short, fresh sessions, not better rule-following. Each rests on a source that tested something nearby, not Agent Specs itself:
  - [Evidence] Token economy: on a conversational memory benchmark, every model scored significantly higher with a focused prompt of about 300 tokens than with the full 113k-token history ([Chroma, 2025](https://www.trychroma.com/research/context-rot)). Caveat: the focused prompts were selected in advance.
  - [Established] Isolation: a Claude Code subagent works in a separate context window and hands back only a summary ([Claude Code docs](https://code.claude.com/docs/en/sub-agents)).
  - [Evidence] Short sessions: each extra function an agent wrote was associated with about 5.6% lower odds of compliance ([McMillan, 2026](https://arxiv.org/abs/2605.10039)). Caveat: the trend was found after the fact, and the study did not test whether fresh sessions or subagents fix it.
- [Proposal] Index-and-leaf plans have no head-to-head test. We found no study that runs the same tasks with a plan split into plan.md and phase files, with one plan file and with no plan, so the split is a design choice, not a finding.
- [Evidence] Results come mostly from specific agents and repositories and may not transfer. One study used four agent setups on Python repositories ([Gloaguen et al., 2026](https://arxiv.org/abs/2602.11988)), another one agent on 124 small pull requests from 10 repositories, measuring speed but not correctness ([Lulla et al., 2026](https://arxiv.org/abs/2601.20404)), and the file-length study mainly one model on two codebases. Caveat: models and harnesses change fast, and most of these sources are preprints or vendor posts.

### Untested parts of Agent Specs

No external source supports these parts of the design. Treat them as choices to test on your own work.

- [Heuristic] The plan.md budget of about 60–80 lines keeps the index cheap to load in every phase; no study measured it. See [Size budgets](/reference/size-budgets/).
- [Heuristic] The escalation triggers. About 150 plan.md lines has no source at all. About 40% of the context window comes from one team, which has since switched to a fixed 100k tokens ([HumanLayer, 2026](https://www.humanlayer.dev/blog/long-context-isnt-the-answer)). See [Sizing](/concepts/sizing/).
- [Proposal] The HANDOFF.md template. No study tests whether a fixed report helps the next phase; its fields follow Anthropic's qualitative advice on briefing subagents ([Anthropic, 2025](https://www.anthropic.com/engineering/multi-agent-research-system)), not a measurement.
- [Proposal] Output scanning and hashed source manifests as defences. No source supports either.
  - [Evidence] Scanners can be evaded: an adaptive attacker got past one open-source skill scanner in up to 97% of runs ([Kaiser and Dhar, 2026](https://arxiv.org/abs/2609.39607)). Caveat: one scanner, success judged by a model rather than people, and a preprint.
- [Proposal] AGENTS.md as the always-read router. No source says every agent loads it every session.
  - [Established] Loading differs by tool: Claude Code, for one, reads AGENTS.md by default only when no CLAUDE.md exists ([Claude Code docs](https://code.claude.com/docs/en/memory)).
- [Heuristic] JSON for state rests on one vendor's experience that models overwrite JSON less often than Markdown, with no published data ([Anthropic, 2025](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)).
- [Proposal] Phase files of about 100 lines, the one-hop rule, landing spots and the sizing gate as a whole are design choices with no study behind them.
- [Proposal] The review phase. We found no study that compares a fresh-context reviewer with the same agent checking its own work on coding tasks; the rule rests on vendor advice and on studies of self-correction in reasoning and planning tasks.
- [Proposal] Separate runtime values for parallel phases, such as ports, temp folders and databases, and orchestrator-owned shared files. One tool assigns ports per workspace ([Conductor](https://www.conductor.build/docs/reference/environment-variables)), but we found no study that tests whether these rules prevent collisions.
- [Proposal] A whole-word term-list leak check misses spelling variants, changed casing and run-together words, and its miss rate is unmeasured.

### Context limits

- [Established] Anthropic matches long-horizon techniques to the task: compaction for extended back-and-forth, note-taking for iterative work with clear milestones, and multi-agent setups for complex research where parallel exploration pays off. Source: [Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) (anthropic.com). Caveat: This is qualitative vendor guidance, not a comparative evaluation. `a-context-choose-technique`
- [Established] Anthropic defines compaction as summarizing a conversation that is nearing the context limit and restarting with the summary, and warns that compacting too aggressively can drop details whose importance only shows up later. Source: [Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) (anthropic.com). Caveat: The post describes the technique and offers no measurement of how much is lost. `a-context-compaction`
- [Established] Anthropic's applied AI team argues that context is a finite resource with diminishing returns, because a model's recall falls as the number of tokens in its context grows. Sources: [Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) (anthropic.com); [Best practices for Claude Code](https://code.claude.com/docs/en/best-practices) (code.claude.com). Caveat: This is a vendor position based on earlier needle-in-a-haystack studies; the post adds no new data. Anthropic also says degradation is a gradient, not a cliff. `a-context-finite`
- [Established] Anthropic defines good context engineering as finding the smallest set of high-signal tokens that makes the desired outcome most likely, and notes that minimal does not have to mean short. Source: [Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) (anthropic.com). Caveat: This is a guiding principle, not a size rule. It gives no token or line numbers. `a-context-smallest-set`
- [Established] Anthropic reports that, without this structure, agents tried to build the whole app at once, ran out of context mid-feature, or later declared the project done too early, and that compaction alone did not prevent this. Source: [Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents) (anthropic.com). Caveat: Qualitative observations from one web-app task with Opus 4.5. No failure rates are given. `a-harness-failure-modes`
- [Established] The Claude Code docs state that model performance degrades as the context window fills, and call context the most important resource to manage. Sources: [Best practices for Claude Code](https://code.claude.com/docs/en/best-practices) (code.claude.com); [Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) (anthropic.com). Caveat: This is a vendor statement and gives no fill level at which degradation starts. `a-cc-context-degrades`
- [Established] Anthropic's authoring guide treats the context window as shared by everything the model needs, and advises adding only information the model does not already have. Source: [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices) (platform.claude.com). Caveat: What counts as already known depends on the model, so it should be checked against each model in use. `a-skill-concise`
- [Established] The Memory Bank files form a hierarchy built on projectbrief.md, and Cline's custom instructions tell it to read every memory-bank file at the start of every task, with activeContext.md changing most often. Source: [Memory Bank](https://docs.cline.bot/features/memory-bank) (docs.cline.bot). Caveat: Reading every file each task means the whole bank costs context every time; the official pages read gave no size limit for the files. `c-cline-read-all`
- [Evidence] In a simulated stock-trading environment with competing pressures, all four tested models drifted from their system-prompt goal to some degree, though a scaffolded Claude 3.5 Sonnet kept near-perfect adherence beyond 100,000 tokens. Source: [Technical Report: Evaluating Goal Drift in Language Model Agents](https://arxiv.org/abs/2505.02709) (arxiv.org). Caveat: One simple simulated environment that the authors say is too simple to compare frontier models; 2024-era models (Claude 3.5 Sonnet and Haiku, GPT-4o and 4o mini); prompt-given binary goals under unusually explicit pressure; reasoning models not tested. `b-goal-drift`
- [Evidence] The goal-drift authors link drift to models increasingly copying patterns from their own earlier actions as context grows, but describe this evidence as only suggestive. Source: [Technical Report: Evaluating Goal Drift in Language Model Agents](https://arxiv.org/abs/2505.02709) (arxiv.org). Caveat: Most of the underlying correlations were not statistically significant; single environment. `b-goal-drift-pattern`
- [Evidence] In Chroma's context-rot report, models did worse when the surrounding filler text was logically coherent than when its sentences were shuffled. Source: [Context Rot: How Increasing Input Tokens Impacts LLM Performance](https://www.trychroma.com/research/context-rot) (trychroma.com). Caveat: Needle-in-a-haystack setup; the authors call the result surprising and do not explain it; relevance to structured instruction files is untested. `b-context-rot-coherence`
- [Evidence] Adding a single topically related but non-answering passage lowered accuracy, and adding four lowered it further. Source: [Context Rot: How Increasing Input Tokens Impacts LLM Performance](https://www.trychroma.com/research/context-rot) (trychroma.com). Caveat: Distractor effects were not uniform across distractors or model families; synthetic retrieval task. `b-context-rot-distractors`
- [Evidence] On a conversational memory benchmark (LongMemEval), every model scored significantly higher with a focused prompt of about 300 tokens than with the full history of about 113k tokens. Source: [Context Rot: How Increasing Input Tokens Impacts LLM Performance](https://www.trychroma.com/research/context-rot) (trychroma.com). Caveat: The focused prompts contained only the relevant parts, selected in advance; shows the value of removing irrelevant context, not a specific token budget. `b-context-rot-focused`
- [Evidence] A technical report testing 18 LLMs found that performance grew less reliable as input length increased, even on simple tasks such as retrieving a planted fact or repeating a word sequence. Source: [Context Rot: How Increasing Input Tokens Impacts LLM Performance](https://www.trychroma.com/research/context-rot) (trychroma.com). Caveat: Vendor report from a retrieval company, not peer reviewed; synthetic tasks with difficulty held constant; mid-2025 models (e.g. GPT-4.1, Claude 4, Gemini 2.5, Qwen3); the authors do not explain the mechanism. `b-context-rot-length`
- [Evidence] In over 200,000 simulated conversations across 15 LLMs and six tasks, revealing an instruction in pieces over several turns cut performance by 39% on average compared with giving it all at once, mostly through a 112% rise in unreliability rather than a 16% loss in aptitude. Source: [LLMs Get Lost In Multi-Turn Conversation](https://arxiv.org/abs/2505.06120) (arxiv.org). Caveat: Simulated users and deliberately underspecified sharded instructions; chat tasks, not agentic coding runs; the paper's Figure 1 gives the drop as 35%; lowering temperature did not fix it. `b-multiturn-drop`
- [Evidence] With 20 documents and the answer placed mid-context, GPT-3.5-Turbo scored as low as 53.8%, below the 56.1% it scored with no documents at all. Source: [Lost in the Middle: How Language Models Use Long Contexts](https://arxiv.org/abs/2307.03172) (arxiv.org). Caveat: Worst-case positions only, on NaturalQuestions-Open; the 30-document comparison used the 16K variant of GPT-3.5-Turbo, not the same model. `b-lost-middle-closed-book`
- [Evidence] In multi-document question answering and key-value retrieval, language models were most accurate when the relevant information was at the start or end of the input and least accurate when it sat in the middle. Source: [Lost in the Middle: How Language Models Use Long Contexts](https://arxiv.org/abs/2307.03172) (arxiv.org). Caveat: 2023 models (GPT-3.5-Turbo, Claude 1.3, MPT-30B-Instruct, LongChat-13B and others) on retrieval tasks with 10-30 documents; newer models may differ; a 2026 study found no position effect inside a 250-line configuration file. `b-lost-middle-u`
- [Evidence] Moving the target instruction from line 2 to line 250 of a 250-line configuration file produced no detectable position effect and no lost-in-the-middle U-shape. Source: [Instruction Adherence in Coding Agent Configuration Files: A Factorial Study of Four File-Structure Variables](https://arxiv.org/abs/2605.10039) (arxiv.org). Caveat: A failure to reject without Bayes-factor support, not proof of no effect; the design rules out contrasts above about 6 percentage points; the file was roughly 2-3k tokens and the author notes the U-shape is usually seen at much longer contexts. `b-config-position-null`
- [Evidence] Compliance fell as a session went on: each additional function the agent wrote was associated with about 5.6% lower odds of following the instruction (OR 0.944, 95% CI 0.937-0.951), and in runs with any miss the median first miss came at the fourth function. Source: [Instruction Adherence in Coding Agent Configuration Files: A Factorial Study of Four File-Structure Variables](https://arxiv.org/abs/2605.10039) (arxiv.org). Caveat: Identified during analysis, not pre-specified; the trend is non-monotonic and detectable on two of three multi-function tasks; sessions of up to 81 functions in single-turn mode; it does not test whether fresh sessions, subagents or re-injected rules fix it. `b-within-session-decay`
- [Heuristic] A practitioner taxonomy names four ways long contexts fail: poisoning (an error enters and keeps being referenced), distraction (the model leans on the context over its training), confusion (irrelevant content degrades answers) and clash (new information or tools contradict earlier context). Source: [How Long Contexts Fail](https://www.dbreunig.com/2025/06/22/how-contexts-fail-and-how-to-fix-them.html) (dbreunig.com). Caveat: A blog post synthesising other reports; the categories are descriptive labels, not measured failure rates. `b-context-failure-taxonomy`
- [Heuristic] HumanLayer's 'frequent intentional compaction' runs research, plan and implement as separate steps, distils searches, code-flow notes and logs into structured artefacts (a research doc, a plan, and status written back into the plan after each verified phase), and aims to keep context use around 40-60%. Source: [Advanced Context Engineering for Coding Agents](https://www.humanlayer.dev/blog/advanced-context-engineering) (humanlayer.dev). Caveat: Practitioner method from one team's experience in Aug 2025; the 40-60% band depends on problem complexity and is not measured in a controlled study. `c-humanlayer-fic`
- [Heuristic] HumanLayer states that frontier thinking models follow roughly 150-200 instructions with reasonable consistency and that Claude Code's own system prompt already uses about 50, leaving a limited budget for instruction files. Source: [Writing a good CLAUDE.md](https://www.humanlayer.dev/blog/writing-a-good-claude-md) (humanlayer.dev). Caveat: The 150-200 figure is the author's reading of arXiv:2507.11538 (not stated in its abstract) and the \~50 is the author's own count; the post itself concedes the topic has not been rigorously studied. `c-humanlayer-instruction-budget`
- [Heuristic] HumanLayer used to warn at about 40% of Claude Sonnet's usable 168k-token window to keep agents out of the 'dumb zone', and in March 2026 moved the warning for long-context models to a fixed 100k tokens after seeing instruction adherence degrade well inside that range. Source: [Long-Context Isn't the Answer](https://www.humanlayer.dev/blog/long-context-isnt-the-answer) (humanlayer.dev). Caveat: Operational threshold from one team's experience, not a benchmark; the threshold itself shifted from a percentage to an absolute token count, so treat \~40% as a rough guide, not a law. `c-humanlayer-dumb-zone`

### Sizing and file length

- [Established] Vendor size guidance for instruction files consistently favors short files: under 500 lines for SKILL.md and for Cursor rules, under 200 lines per CLAUDE.md, and about 100 lines for OpenAI's AGENTS.md map. Sources: [Specification](https://agentskills.io/specification) (agentskills.io); [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices) (platform.claude.com); [Rules](https://cursor.com/docs/rules) (cursor.com); [How Claude remembers your project](https://code.claude.com/docs/en/memory) (code.claude.com); [Harness engineering: leveraging Codex in an agent-first world](https://openai.com/index/harness-engineering/) (openai.com). Caveat: Each figure is a vendor recommendation or one team's practice. None comes from a published experiment, and the figures apply to different file types. `a-size-guidance-convergence`
- [Established] Vendors advise skipping a formal plan for small changes: Claude Code says to skip planning when the diff fits in one sentence, and openai-agents-python makes ExecPlans optional for trivial fixes such as typos. Sources: [Best practices for Claude Code](https://code.claude.com/docs/en/best-practices) (code.claude.com); [PLANS.md (openai/openai-agents-python)](https://github.com/openai/openai-agents-python/blob/main/PLANS.md) (github.com). Caveat: Both are rules of thumb from vendor docs. Neither defines task size beyond examples. `a-size-gate-small-tasks`
- [Established] The Claude Code memory docs set a target of under 200 lines per CLAUDE.md file, because longer files use more context and reduce adherence. They also note that @-imports organize a file but do not reduce its context cost. Source: [How Claude remembers your project](https://code.claude.com/docs/en/memory) (code.claude.com). Caveat: The 200-line target is vendor guidance specific to Claude Code and is not tied to a cited study. `a-cc-claudemd-200`
- [Established] The Agent Skills spec, Anthropic's authoring guide and the Claude Code docs all advise keeping the SKILL.md body under 500 lines and moving detailed material into separate files. Sources: [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices) (platform.claude.com); [Specification](https://agentskills.io/specification) (agentskills.io); [Extend Claude with skills](https://code.claude.com/docs/en/skills) (code.claude.com). Caveat: This is a guideline. No source publishes a measurement showing that 500 lines is a threshold. `a-skill-body-500`
- [Established] Cursor advises keeping rules under 500 lines, splitting large rules into smaller composable ones, and adding rules only after the agent repeats the same mistake. Source: [Rules](https://cursor.com/docs/rules) (cursor.com). Caveat: Vendor guidance with no data behind the 500-line figure. `a-cursor-500`
- [Established] The openai-agents-python repo requires an ExecPlan for multi-step or multi-file work, new features, refactors, or tasks expected to take more than about an hour, and makes one optional for trivial fixes. Sources: [PLANS.md (openai/openai-agents-python)](https://github.com/openai/openai-agents-python/blob/main/PLANS.md) (github.com); [AGENTS.md (openai/openai-agents-python)](https://github.com/openai/openai-agents-python/blob/main/AGENTS.md) (github.com). Caveat: This is one repository's policy, and the one-hour cutoff is approximate. `a-execplan-when`
- [Established] Current BMad docs size planning to the work through four paths: trivial, one-session, epic-sized (adds a spec and stories, built one story at a time) and project-sized (several epics or roughly 20+ sessions, adding shared product, UX and technical contracts). Source: [Choose a Planning Path](https://docs.bmad-method.org/plan/choose-a-planning-path/) (docs.bmad-method.org). Caveat: Vendor docs for the 2026 method (v6.12/v7 era), which differs substantially from v4. `c-bmad-planning-paths`
- [Established] Kiro's own guidance says a quick chat fix is fine for straightforward issues such as typos, offers Quick Spec to generate all three files in one pass without approval gates, and says specs are designed to be version-controlled beside the code and refined as the project evolves. Sources: [Best practices (Specs)](https://kiro.dev/docs/specs/best-practices/) (kiro.dev); [Specs](https://kiro.dev/docs/specs/) (kiro.dev). Caveat: Vendor guidance, not measured; it partly answers Böckeler's 2025 criticisms (overhead on small tasks, no spec-anchored use). `c-kiro-sizing-guidance`
- [Evidence] When 20 models had to follow between 10 and 500 simple keyword-inclusion instructions at once, accuracy fell as the count rose, the best model (Gemini 2.5 Pro) reached 68.9% at 500, and models tended to miss later instructions more than earlier ones. Source: [How Many Instructions Can LLMs Follow at Once?](https://arxiv.org/abs/2507.11538) (arxiv.org). Caveat: Measures many simultaneous trivial instructions in one report-writing task, not file length or coding agents; English business vocabulary; 2025 models; complements, rather than contradicts, the McMillan size null, which varied filler around one target rule. `b-instruction-density`

Source: [Instruction Adherence in Coding Agent Configuration Files: A Factorial Study of Four File-Structure Variables](https://arxiv.org/abs/2605.10039) (arxiv.org). Caveat: The target was a trivial comment marker on TypeScript functions; single-turn --print mode; mainly Sonnet 4.6 on two codebases; files above 500 lines not tested; it does not show long files are free, since they still cost tokens in every session. `b-config-size-null`

Source: [Instruction Adherence in Coding Agent Configuration Files: A Factorial Study of Four File-Structure Variables](https://arxiv.org/abs/2605.10039) (arxiv.org). Caveat: Five feature tasks on one Next.js codebase; the largest gap rests on a single pair of tasks that differ in many ways, so no modify-versus-write conclusion follows. `b-task-over-structure`
- [Evidence] Böckeler found Kiro the most lightweight of the three tools, yet on a small bug its requirements document still produced 4 user stories with 16 acceptance criteria, which she likened to cracking a nut with a sledgehammer. Source: [Understanding Spec-Driven-Development: Kiro, spec-kit, and Tessl](https://martinfowler.com/articles/exploring-gen-ai/sdd-3-tools.html) (martinfowler.com). Caveat: A single hands-on trial by one practitioner on the Oct 2025 version; Kiro has since added bugfix specs and Quick Spec, and its docs now say a chat fix suits trivial issues. `c-bockeler-kiro-small-bug`
- [Evidence] Using spec-kit on a feature she sized as a 3-5 point story, Böckeler found the generated Markdown files repetitive (with each other and with existing code) and tedious to review, and judged that plain AI-assisted coding would have taken no longer and felt more in control. Source: [Understanding Spec-Driven-Development: Kiro, spec-kit, and Tessl](https://martinfowler.com/articles/exploring-gen-ai/sdd-3-tools.html) (martinfowler.com). Caveat: One practitioner, one feature, Oct 2025 tool version; she did not finish the full implementation, so this is a qualitative impression, not a measured time comparison. `c-bockeler-speckit-review-burden`
- [Heuristic] Anthropic's lead agent follows effort-scaling rules: one agent with 3 to 10 tool calls for simple fact-finding, 2 to 4 subagents with 10 to 15 calls each for comparisons, and more than 10 subagents for complex research. Source: [How we built our multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system) (anthropic.com). Caveat: These are prompt rules tuned for one research system and were not validated as general thresholds. `a-multiagent-scale-effort`

### AGENTS.md and instruction files

- [Established] The agents.md site says the format is used by more than 60,000 open-source projects, and that the main OpenAI repository had 88 AGENTS.md files when the page was written. Source: [AGENTS.md](https://agents.md/) (agents.md). Caveat: These are undated, self-reported counts from the format's own site. `a-agentsmd-adoption`
- [Established] AGENTS.md is plain Markdown with no required fields or headings, meant as a predictable place for agent-focused context such as build, test and style instructions that would clutter a README. Source: [AGENTS.md](https://agents.md/) (agents.md). Caveat: Because there is no schema, content and quality vary widely between repositories. `a-agentsmd-format`
- [Established] AGENTS.md supports nested files for subprojects: agents read the nearest file in the directory tree, the file closest to the edited file wins when instructions conflict, and explicit user prompts override everything. Sources: [AGENTS.md](https://agents.md/) (agents.md); [Rules](https://cursor.com/docs/rules) (cursor.com). ### Progressive disclosure

- [Established] Skills load in three tiers: about 100 tokens of name and description per skill at startup, a full SKILL.md body (recommended under 5,000 tokens) when the skill activates, and bundled files only when they are needed. Sources: [Specification](https://agentskills.io/specification) (agentskills.io); [Agent Skills (overview)](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview) (platform.claude.com). Caveat: These are approximate design budgets, not measured limits. Real metadata cost grows with description length. `a-skill-disclosure-budgets`
- [Established] Skill authors should link every reference file directly from SKILL.md (one level deep), because Claude may only preview files reached through nested references, for example with head -100, and miss content. Sources: [Specification](https://agentskills.io/specification) (agentskills.io); [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices) (platform.claude.com). Caveat: Anthropic says partial reads may happen. It does not say they always happen, and it gives no frequency. `a-skill-refs-one-level`
- [Established] Once an agent decides to activate a skill, it loads the whole SKILL.md file, so longer content belongs in referenced files. Source: [Specification](https://agentskills.io/specification) (agentskills.io). Caveat: This describes expected client behavior. Individual agents may implement loading differently. `a-skill-whole-body-loads`
- [Established] Anthropic describes 'just in time' retrieval: the agent holds lightweight references such as file paths and loads data through tools at runtime. Claude Code mixes this with CLAUDE.md files that are loaded up front. Source: [Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) (anthropic.com). Caveat: Anthropic notes that exploring at runtime is slower than precomputed retrieval, and that agents without good guidance can waste context on dead ends. `a-context-jit`
- [Established] Anthropic calls progressive disclosure the core design principle of Agent Skills: metadata is preloaded, SKILL.md is read when relevant, and bundled files are opened only as needed, so a skill can bundle an effectively unbounded amount of context. Sources: [Equipping agents for the real world with Agent Skills](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills) (anthropic.com); [Agent Skills (overview)](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview) (platform.claude.com). Caveat: 'Unbounded' assumes the agent has filesystem and code-execution tools and only reads what it needs. `a-skill-progressive-disclosure-principle`
- [Established] Scripts bundled with a skill can be run without loading their code into context, so only their output costs tokens and the result is repeatable. Sources: [Equipping agents for the real world with Agent Skills](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills) (anthropic.com); [Agent Skills (overview)](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview) (platform.claude.com). Caveat: This requires an agent that can execute code. The output still uses context. `a-skill-scripts-deterministic`
- [Established] Anthropic recommends a table of contents at the top of any reference file longer than 100 lines, so that a partial read still shows everything the file covers. Source: [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices) (platform.claude.com). Caveat: Vendor guidance for Claude; the 100-line trigger is not justified with data. `a-skill-ref-toc`
- [Established] Cursor advises referencing files rather than copying their contents into rules, so rules stay short and don't go stale. A referenced file is read with tools when needed, not inlined into the prompt. Source: [Rules](https://cursor.com/docs/rules) (cursor.com). Caveat: Anything that must always be in context has to go in the rule body itself. `a-cursor-reference`
- [Evidence] Splitting the configuration into CLAUDE.md plus AGENTS.md, or adding nested CLAUDE.md files, gave no detectable compliance gain over a single file (67.7%, 68.2% and 61.7%). Source: [Instruction Adherence in Coding Agent Configuration Files: A Factorial Study of Four File-Structure Variables](https://arxiv.org/abs/2605.10039) (arxiv.org). Caveat: A failure to reject without Bayes-factor support; the 6-point dip for nested files did not survive correction; splitting may still pay off through token savings and scoping, which this study did not measure. `b-config-split-null`

### Agent Skills

- [Established] A skill description must be 1 to 1,024 characters and should say what the skill does and when an agent should use it, with keywords that help an agent match it to tasks. Sources: [Specification](https://agentskills.io/specification) (agentskills.io); [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices) (platform.claude.com). Caveat: The 1,024 limit is the spec's. Claude Code's listing applies a separate 1,536-character cap to description plus when_to_use. `a-skill-description-limit`
- [Established] A skill name must be 1 to 64 characters of lowercase letters, digits and hyphens, cannot start or end with a hyphen or contain two hyphens in a row, and must match its parent directory name. Sources: [Specification](https://agentskills.io/specification) (agentskills.io); [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices) (platform.claude.com). Caveat: Anthropic's platform also bans XML tags and the words 'anthropic' and 'claude' in names. Source: [Specification](https://agentskills.io/specification) (agentskills.io). Caveat: The spec notes that most skills do not need compatibility. What allowed-tools does depends on the client; in Claude Code it pre-approves tools but restricts none. `a-skill-optional-field-limits`
- [Established] The Agent Skills specification requires only two frontmatter fields, name and description; license, compatibility, metadata and allowed-tools are optional. Caveat: This corrects the prior report's 'forked subagent' wording: despite the name, the subagent does not inherit the conversation. `a-cc-skill-context-fork`

Source: [Extend Claude with skills](https://code.claude.com/docs/en/skills) (code.claude.com). Caveat: This is Claude Code behavior. - [Established] Anthropic advises matching how specific instructions are to how fragile the task is: loose text guidance where many approaches work, and exact scripts with few or no parameters where operations are error-prone or must follow a fixed sequence. Source: [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices) (platform.claude.com). Caveat: This is a qualitative design rule with no evaluation data behind it. `a-skill-degrees-freedom`

Source: [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices) (platform.claude.com). Caveat: Vendor guidance written for Claude. Its effect on other agents has not been tested. `a-skill-third-person`

Source: [AGENTS.md outperforms skills in our agent evals](https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals) (vercel.com). Caveat: One vendor's internal eval on one framework, targeting Next.js 16 APIs absent from model training data; number of cases, models and harness are not disclosed; it measures API-knowledge retrieval, not procedural workflows; not peer reviewed. `c-vercel-pass-rates`

Caveat: Same single-vendor Next.js 16 eval; undisclosed models and harness; trigger reliability likely depends on the skill description and the harness, which the post does not vary systematically. `c-vercel-skill-never-invoked`

Caveat: Illustrated with individual eval cases (e.g. a 'use cache' test that needed a config change), not a systematic wording study; the author frames the explanation as a working theory. `c-vercel-wording-fragile`
- [Heuristic] The Vercel author still recommends skills for vertical, action-specific workflows a user triggers explicitly (such as a framework upgrade or migration), with passive AGENTS.md context for broad framework knowledge.
